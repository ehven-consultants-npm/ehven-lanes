# Repository instructions

## Package architecture

`@ehven/lanes` is a framework-agnostic CSS package.

The package must remain usable in Astro, Starlight, WordPress, Webflow, static HTML, and other environments without requiring framework-specific runtime code.

Do not introduce JavaScript layout measurement or item-placement logic into the core package.

## Source of truth

`src/lanes.css` is the sole CSS source of truth.

Files under `dist/` are generated by `scripts/build.mjs`. Never edit generated distribution files manually.

## Public API

The following names are public API:

- `.ehven-lanes`
- `--ehven-lanes-gap`
- `--ehven-lanes-lane-minimum`
- `--ehven-lanes-flow-tolerance`

Renaming or removing public API requires a SemVer-compatible release decision and corresponding migration documentation.

## Progressive enhancement

The CSS Multi-column Layout implementation is the dependable baseline.

Browsers supporting `display: grid-lanes` receive the native Grid Lanes enhancement through `@supports`.

Changes must preserve a usable no-JavaScript fallback.

## Delivery contract

Every release must provide the same generated CSS through:

1. The public npm package.
2. Versioned GitHub Release assets.

The readable and minified CSS files in the npm tarball must be byte-for-byte identical to their corresponding GitHub Release assets.

See `docs/delivery.md` and `docs/releasing.md`.
